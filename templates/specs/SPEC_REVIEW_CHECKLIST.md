# Spec Review Checklist

## User Value

- [ ] The target user is named.
- [ ] The problem is concrete.
- [ ] The expected behavior is testable.

## Scope

- [ ] Non-goals are explicit.
- [ ] Acceptance criteria are measurable.
- [ ] Dependencies and tool permissions are named.

## Implementation Readiness

- [ ] Ownership boundaries are clear.
- [ ] Security/privacy implications are stated.
- [ ] Required docs, tests, and plans are listed.
